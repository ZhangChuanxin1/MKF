# Publishing the artifact on GitHub

These instructions describe publication; running artifact checks does not
upload code. Confirm the target repository, source license, and disclosure
scope before pushing. Retain the third-party license files.

The project name is `MKF`. This source release preserves exact file bytes
with `.gitattributes` because the publication manifest binds those bytes.
Do not enable line-ending conversion for manifest-bound sources without
reviewing and regenerating the manifest.

## Validate the source

From the artifact root:

```powershell
py -3 scripts/publication_scan.py --verify-manifest
py -3 -m unittest discover -s tests -v
pwsh -NoProfile -File scripts/run_suite.ps1 -Profile smoke
```

If an intentional source/documentation edit changes the manifest, review
the edit before running `scripts/publication_scan.py --write-manifest`.
Regenerating a manifest is not a substitute for reviewing unknown changes.

Use the source ZIP generated by `scripts/make_source_zip.py`, rather than
copying local caches, datasets, fixtures or execution logs.

## Existing repository

Clone into a new local directory. Create a new branch, then extract the
reviewed source ZIP into a new artifact subdirectory. This keeps existing
repository files and history available and avoids mixing an artifact's
source manifest with unrelated repository files. Do not overwrite an
uncommitted working directory.

Run the publication check from inside the extracted artifact. Review
`git diff` and `git status --short`; stage only the intended source and
documentation paths. Then commit and push the new branch. Review the branch
on GitHub before merging it into the default branch. Do not force-push to
bypass a conflict or authentication error.

## Empty repository

For a genuinely empty target, initialize a local repository at the artifact
root, stage the reviewed source, create a commit, add the target HTTPS remote,
and push the initial branch. Do not use this workflow to overwrite an
existing repository with unrelated history.

GitHub documents the command-line import workflow in
[Adding locally hosted code to GitHub](https://docs.github.com/en/migrations/importing-source-code/using-the-command-line-to-import-source-code/adding-locally-hosted-code-to-github).

## Authentication and disclosure

For HTTPS, use Git Credential Manager or GitHub CLI authentication as described
in [GitHub's credential documentation](https://docs.github.com/en/get-started/git-basics/caching-your-github-credentials-in-git).
Never embed a password or token in a remote URL, source file, README, or chat.

An artifact content scan does not certify double-blind anonymity or remove
old repository history. Review the account, commit metadata, tags, release
assets, and previous commits separately. Third-party legal notices must not
be removed for anonymization.

After publishing, download a clean copy and repeat the source-manifest and
smoke checks. Hardware configuration and projected figure inputs must remain
distinguished from completed board measurements.
